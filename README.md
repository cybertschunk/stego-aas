# Stego-aaS (Steganography as a Service)

A web application that provides a simple API for encoding and decoding hidden messages using the **SparSamp** steganographic protocol. SparSamp embeds secret messages within LLM-generated text in a provably secure manner, making the presence of hidden information undetectable.

## Overview

Stego-aaS is built on top of the **SparSamp** algorithm, which provides provably secure linguistic steganography. Unlike traditional steganography that hides data in images or audio, SparSamp conceals messages within natural language text generated by large language models (LLMs).

The service encapsulates the complexity of SparSamp behind a clean REST API, allowing developers to easily integrate steganographic capabilities into their applications without needing to understand the underlying cryptographic and information-theoretic details.

### What is SparSamp?

SparSamp (Sparse Sampling) is a steganographic protocol that differs from traditional steganographic methods by being both **provably secure** and highly **efficient**. Unlike traditional approaches that hide data in images or audio files, SparSamp:
- Embeds messages within LLM-generated text
- Provides provable security guarantees through information-theoretic foundations
- Makes hidden messages statistically undetectable
- Uses sparse sampling techniques to efficiently encode information in token selection

## Features

### Core Features

- **BackCheck Implementation**: Advanced tokenization ambiguity resolution using a tree-based backtracking algorithm with periodic checkpoints. Ensures accurate decoding even when different tokenizations of the same text are possible.

- **Simple REST API**: Clean, straightforward endpoints for encoding and decoding operations. Easy integration with any application.

- **Singleton Model Management**: Efficient resource usage with a thread-safe singleton pattern for managing the GPT-2 model and tokenizer.

### Technical Features

- **Modular Architecture**: Clean separation of concerns with dedicated modules for encoding, decoding, and BackCheck logic
- **Django Integration**: Built on Django REST Framework for robust API handling
- **Comprehensive Testing**: Full test suite covering short messages, long messages, and multiple text encoding

### Module Breakdown

- **model_manager.py**: Thread-safe singleton managing GPT-2 model and tokenizer lifecycle
- **encoding.py**: Message encoding logic with checkpoint insertion
- **decoding.py**: Core blind decoding algorithm
- **backcheck.py**: Tree-based tokenization ambiguity resolution
- **sparsamp_utils.py**: Utility functions for probability calculations and conversions
- **constants.py**: Configuration parameters for the SparSamp algorithm

## Installation

### Prerequisites

- Python 3.13 or higher
- pip (Python package manager)
- 4GB+ RAM (for GPT-2 model)
- Optional: CUDA-compatible GPU (for acceleration)

### GPU Support
- See **`GPU_SUPPORT.md`** for a comprehensive guide for GPU acceleration:
- The project is GPU ready, but Python 3.13 has no GPU library support as of 11.2025. 

### Setup

1. **Clone the repository**
   ```bash
   git clone https://github.com/yourusername/stego-aas.git
   cd stego-aas
   ```

2. **Create a virtual environment**
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # On Windows: .venv\Scripts\activate
   ```

3. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

4. **Run database migrations**
   ```bash
   cd stego-aas/stegoaas
   python manage.py migrate
   ```

5. **Start the development server**
   ```bash
   python manage.py runserver
   ```

The API will be available at `http://localhost:8000/`

## Usage

### Encoding a Message

**Request:**
```bash
curl -X POST http://localhost:8000/api/encode/ \
  -H "Content-Type: application/json" \
  -d '{
    "context": "Once upon a time",
    "message": "attack@dawn",
    "seed": 12345
  }'
```

**Response:**
```json
{
  "stego_messages": [
    " and then he came to Boston.\n\nAt his earliest youth was fruitless, perhaps unh..."
  ]
}
```

### Decoding a Message

**Request:**
```bash
curl -X POST http://localhost:8000/api/decode/ \
  -H "Content-Type: application/json" \
  -d '{
    "context": "Once upon a time",
    "stego_messages": [
      " and then he came to Boston.\n\nAt his earliest youth was fruitless, perhaps unh..."
    ],
    "seed": 12345
  }'
```

**Response:**
```json
{
  "decoded_message": "attack@dawn",
  "attempts_per_message": [1]
}
```

## API Reference

### POST /api/encode/

Encodes a secret message into steganographic text.

**Request Body:**
- `context` (string, required): The context text that precedes the generated steganographic text
- `message` (string, required): The secret message to hide
- `seed` (integer, required): Random seed for reproducible encoding

**Response:**
- `stego_messages` (array of strings): List of generated text segments containing the hidden message

**Status Codes:**
- `200 OK`: Encoding successful
- `400 Bad Request`: Invalid input parameters
- `500 Internal Server Error`: Encoding failed

### POST /api/decode/

Decodes a secret message from steganographic text.

**Request Body:**
- `context` (string, required): The original context text used during encoding
- `stego_messages` (array of strings, required): The steganographic text segments to decode
- `seed` (integer, required): The same random seed used during encoding

**Response:**
- `decoded_message` (string): The recovered secret message
- `attempts_per_message` (array of integers): Number of BackCheck attempts required for each message

**Status Codes:**
- `200 OK`: Decoding successful
- `400 Bad Request`: Invalid input parameters
- `500 Internal Server Error`: Decoding failed

## Technical Details

### SparSamp Algorithm

The implementation uses the following parameters:

| Parameter | Value | Description |
|-----------|-------|-------------|
| BLOCK_SIZE | 32 bits | Size of each message block |
| BLOCKS_PER_INTERVAL | 4 | Number of blocks before checkpoint |
| TOP_P | 0.95 | Nucleus sampling threshold |
| CONTEXT_WINDOW_SIZE | 1022 tokens | Maximum context size |
| MIN_TOKEN_LENGTH | 100 tokens | Minimum tokens per block |
| MAX_TOKEN_LENGTH | 1000 tokens | Maximum tokens (safety limit) |
| MODEL_NAME | openai-community/gpt2 | Language model used |

### BackCheck Algorithm

The BackCheck algorithm addresses tokenization ambiguity:

1. **Tree Construction**: Builds a tree of possible tokenizations for the steganographic text
2. **Path Selection**: Uses priority rules to select the most likely tokenization:
   - Known correct tokens (verified by checkpoints)
   - Greedy tokenization (default tokenizer behavior)
   - Highest probability alternatives
3. **Verification**: Tests each candidate path using blind decoding
4. **Backtracking**: Falls back to alternatives when verification fails

### Performance Tracking

The decode API returns performance metrics for analysis:
- `attempts_per_message`: Array showing BackCheck attempts needed for each message segment
- Typically requires 1-6 attempts for successful decoding
- Useful for analyzing decoding efficiency and checkpoint effectiveness

### Checkpoint Mechanism

Every `BLOCKS_PER_INTERVAL` blocks, a checkpoint is inserted:
- Contains `BLOCK_SIZE - 8` bits of message data
- Followed by 8 zero bits as a marker
- Allows early detection of decoding errors
- Enables efficient state restoration during BackCheck

### Utility Scripts

The project includes several utility scripts in the root directory:

- **`evaluate_backcheck_performance.py`**: Comprehensive performance benchmarking tool that:
  - Tests BackCheck algorithm with 100 different random seeds
  - Tracks attempts, timing, and success rates
  - Outputs detailed statistics and CSV results
  - Useful for analyzing algorithm efficiency and optimization

- **`test_evaluation.py`**: Quick performance test script:
  - Runs a minimal test with 5 seeds
  - Validates that performance tracking is working
  - Useful for rapid verification during development

- **`verify_device.py`**: GPU/CPU detection and verification tool:
  - Checks CUDA availability and GPU information
  - Verifies which device is being used by the model
  - Helps troubleshoot GPU configuration issues
